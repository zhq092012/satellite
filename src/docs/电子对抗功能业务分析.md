# 电子对抗（CEMA）模拟功能深度解析报告

本报告针对当前系统中的**网络与电磁空间对抗（CEMA - Cyber Electromagnetic Activities）模拟功能**进行深度算法拆解与逻辑评估。系统通过多域物理链路状态、天基轨道运动特性、电磁损耗解算，实现了高逼真度的红蓝对抗推演与效能复盘。

---

## 一、 干扰与打击成功的核心算法与物理因子

战术决策引擎每一分钟（Tick）会对红方可用武器进行背包决策匹配，并在确定目标资产后，通过以下五大空间物理衰减因子对无线电波传播进行精细解算：

### 1. 五大空间物理衰减乘数

#### ① 距离反比损耗 ($attenuation\_dist$)
根据电磁波空间自由传播的平方反比定律，干扰功率随距离的平方呈衰减趋势：
$$attenuation\_dist = \frac{1}{4 \pi \cdot d^2}$$
* **计算逻辑**：对于非网络（Non-CYBER）武器，计算其部署位置与目标资产（如蓝方接收站、无人机）的球面半正矢距离 $d$ (km)。若 $d$ 为 0（例如网络劫持武器），则无此衰减限制。

#### ② 自由空间高程损耗 ($attenuation\_alt$)
若目标为天基资产（卫星），其轨道高程会引入额外的自由空间衰减损耗：
$$attenuation\_alt = \frac{1}{1 + \left(\frac{alt}{100}\right)^2}$$
* **计算逻辑**：天基资产高程 $alt$ (km) 越高，电磁信号越难穿透电离层，损耗比例越大。

#### ③ 地形遮蔽损耗 ($attenuation\_terrain$)
地面终端与雷达接收站信号会受到周围地形的衍射和反射遮蔽阻尼。
* **计算逻辑**：天基资产（Layer = 2 卫星）遮蔽系数为 `1.0` (无地形阻尼)；地面接收终端与雷达接收站（Layer = 0 指挥中心 / Layer = 1 地基接收站），则默认引入 `0.75` 的遮蔽削弱。

#### ④ 多普勒频移及动态追随损耗 ($attenuation\_vel$)
由于蓝方卫星处于高速运动状态（第一宇宙速度附近），高动态移动产生多普勒频移，干扰锁相环存在捕获误差，降低有效接收功率。
* **计算逻辑**：天基卫星资产引入 `0.85` 的极速运动跟踪衰减；空基与地基资产为 `1.0`。

#### ⑤ 天线指向姿态极化折损 ($attenuation\_att$)
天线波束极化方向与指向偏差引起的额外物理极化损失。
* **计算逻辑**：由于星地姿态无法做到实时理想对齐，系统引入 `0.90` 的固定偏角折损系数。

---

### 2. 最终有效干信比（J/S Ratio）公式
将上述衰减链叠加后，干扰机在目标天线输入端产生的有效**干信比（Jamming-to-Signal Ratio, J/S）**计算如下：

$$\text{J/S} = 10 \cdot \log_{10}\left( \frac{P_{jam} \cdot attenuation\_dist \cdot attenuation\_terrain \cdot attenuation\_alt \cdot attenuation\_vel \cdot attenuation\_att}{P_{sig\_recv}} \right)$$

* **基准参数**：
  * 干扰机基准开机发射功率 $P_{jam} = 3000\text{ W}$。
  * 蓝方通信发射端功率 $P_{sig\_recv}$ 同样经过 600km 基准距离的自由空间衰减。

### 3. 拦截成功（isSuccessful）判定决策树

交战动作命中结果判定（0-拦截失败，1-拦截成功）实行**双轨制判定**：

```
                           [判定武器毁伤机制]
                                |
               +----------------+----------------+
               |                                 |
           【软杀伤】 (SOFT/CYBER/EW/DEW)    【硬杀伤】 (HARD/KINETIC)
               |                                 |
       解算 J/S 干信比                          跳过电磁解算
     判断 J/S >= 蓝方门槛                         直接基于武器命中概率
   (final_js >= anti_jam_level)             Math.random() <= successProb
               |                                 (HQ-19 命中率 95%)
               +----------------+----------------+
                                |
                        [判定成功结果]
```

* **软杀伤判定**：需要干扰干信比 $final\_js$ 强于目标本身抗干扰阈值（$threshold$），且满足概率筛选。
* **硬杀伤判定**：直接跳过无线电解算，纯粹通过动能武器的高置信度物理撞击判定（HQ-19 命中概率为 `95%`）。

## 二、 评估的各项指标及计算方式

复盘评估大屏通过以下四个多维维度以及**达成网络自愈时延**指标，对战术方案进行量化画像：

| 指标名称 | 计算公式 | 评估逻辑与物理语义 |
| :--- | :--- | :--- |
| **链路阻断率 (Block Rate)** | $\frac{\text{被阻断或摧毁的链路数}}{\text{总链路数}} \times 100\%$ | 取推演场景第 50 分钟最终状态。值越高说明压制越广。 |
| **冲突控制度 (Conflict Control)** | $\max\left(30, 100 - \frac{TotalCost}{300000} \times 40\right)$ | 评估开销规模。弹药开支越低，得分越高，反映战意和烈度在非战争军事行动（MOOTW）中的克制性。 |
| **效费性价比 (Cost Efficiency)** | $\min\left(95, \max\left(25, \frac{TotalDelay}{TotalCost + 1000} \times 1200\right)\right)$ | 评估**单位金钱换取的时延剥夺效率**。在花较少代价引起极大网络崩塌时该项得分最高。 |
| **红方自扰度 (Self Interference)** | $\min\left(95, \max\left(30, 60 + (Destroyed \times 12) - \frac{TotalCost}{400000} \times 20\right)\right)$ | 频繁使用电磁压制（EW）会产生用频自扰，而动能（KINETIC）硬摧毁不占用频信道，自扰得分越高代表自扰控制越好。 |

### 达成网络自愈时延（Total Delay Achieved）的动态数学模型

自愈时延代表红方通过压制手段夺取的信息流时间控制优势，计算采用**时效累加破坏法**：
1. **软干扰（SOFT Jamming）**：
   $$\text{DelayAdded} = 15\text{s} \times \text{受影响链路数}$$
   电磁波关闭或改频后，蓝方节点通过路由重收敛和备用频率可在极短时间自愈，每次打击仅贡献小额时延。
2. **硬摧毁（HARD Destruction）**：
   $$\text{DelayAdded} = \text{受影响链路数} \times (ScenarioEndTime - CurrentTime)$$
   导弹物理摧毁节点是不可逆的。一旦摧毁，该节点在整个战役余下所有时间（$ScenarioEndTime - CurrentTime$）内都无法工作，其所有受影响的物理链路全部永久崩塌，时延与剩余时长成线性正比。

## 三、 核心代码块与代码解释

### 1. 后端战术交战计算引擎（SQLite Worker）
在 `sqlite.worker.ts` 中，核心交战逻辑处理软硬杀伤、空间衰减和多维时延计算：

```typescript
// ① 更新当前时刻受影响链路状态（软干扰 JAMMED 或硬物理摧毁 DESTROYED）
db.exec({
  sql: `
    UPDATE communication_windows 
    SET link_status = ? 
    WHERE scenario_id = ? AND ? BETWEEN window_start AND window_end
      AND (source_id = ? OR target_id = ?)
  `,
  bind: [newStatus, scenarioId, currentTime, asset.id, asset.id]
});

// ★ 立即捕获受影响链路数
const linksAffected = db.changes();

if (selectedWeapon.kill_type === 'HARD') {
  // ② 硬摧毁：同步摧毁该节点的所有【未来时间窗口】链路，防止其在后续 Tick 恢复
  db.exec({
    sql: `
      UPDATE communication_windows 
      SET link_status = 'DESTROYED' 
      WHERE scenario_id = ? AND window_start > ?
        AND (source_id = ? OR target_id = ?)
        AND link_status != 'DESTROYED'
    `,
    bind: [scenarioId, currentTime, asset.id, asset.id]
  });

  // ③ 更新物理资产本身：抗干扰等级归零，优先级归零，代表节点已物理消失，从目标池永久除名
  db.exec({
    sql: `UPDATE assets SET anti_jam_level = 0, base_priority = 0 WHERE id = ?`,
    bind: [asset.id]
  });
}

// ④ 动态计算本次打击对总体方案自愈时延的贡献
let delayAdded: number;
if (selectedWeapon.kill_type === 'HARD') {
  // 硬摧毁：损伤持续到场景结束
  const remainingSeconds = Math.max(0, scenarioEndTime - currentTime);
  delayAdded = Math.max(1, linksAffected) * remainingSeconds;
} else {
  // 软干扰：可逆短压制，每条链路仅折合 15s 时效延阻
  delayAdded = 15 * Math.max(1, linksAffected);
}
```

#### 【核心解析】：
* **时序状态锁定**：在 `kill_type === 'HARD'` 时，利用 `UPDATE ... WHERE window_start > currentTime` 级联修改属于该节点的所有未来连线预测。这完美杜绝了“已被炸毁的卫星在几分钟后由于过境又开始重新建立传输”的动态数据逻辑 Bug。
* **数据即时捕获**：必须在更新 `assets` 状态之前通过 `db.changes()` 捕获到当前活跃链数，若颠倒顺序则获取的是修改资产（恒为 1 行）而不是修改的通信链路数。

### 2. 前端效能大屏多维评估引擎（AfterActionReview.vue）
在复盘对比时，雷达图的评估算法计算如下：

```typescript
// 效费比计算：将时延收益除以资金代价，并乘以 1200 放大系数
const calcCostEfficiency = (delay: number, cost: number) => 
  Math.min(95, Math.max(25, Math.round((delay / (cost + 1000)) * 1200)));

// 自扰度计算：起步分 60，每物理摧毁一个干扰源，自扰减小(+12分)，大功率干扰使用费越高，电磁自扰增加(-20分范围)
const calcSelfInterference = (cost: number, destroyed: number) => 
  Math.min(95, Math.max(30, Math.round(60 + (destroyed * 12) - (cost / 400000) * 20)));

// 应用评估
const costEfficiencyA = calcCostEfficiency(summaryA.value.totalDelay, summaryA.value.totalCost);
const selfInterferenceA = calcSelfInterference(summaryA.value.totalCost, summaryA.value.destroyedCount);
```

#### 【核心解析】：
* **指标差异分化**：此处的动态算法取代了最初粗暴的常数分级，实现了不同冲突烈度方案（如低烈度电磁干扰与高烈度饱和打击）之间雷达图多维度轮廓的完美分化。
